# llm-conversation Specification

## Purpose

Power conversational interactions using Gemini or DeepSeek models via the Vercel AI SDK, providing warm, family-friendly Vietnamese responses with typing indicators, outbound text splitting, and failure handling.

## Requirements

### Requirement: Conversational Vietnamese generation with Gemini or DeepSeek
The system SHALL use the Vercel AI SDK to prompt the configured LLM provider (Gemini via `@ai-sdk/google` or DeepSeek via `@ai-sdk/deepseek`). The prompt SHALL enforce a warm, informal, family-friendly Vietnamese persona by default (or English if the user writes in English), keeping answers concise and grounded. The prompt construction SHALL enforce strict instruction hierarchy and wrap user turns and memories in structured XML delimiters to isolate untrusted text from system directives.

#### Scenario: General question in Vietnamese
- **WHEN** a family member asks a general question in Vietnamese
- **THEN** the model responds in Vietnamese with a warm, natural, and concise answer

#### Scenario: Question in English
- **WHEN** a user addresses the bot in English
- **THEN** the model generates the reply in English

#### Scenario: Untrusted content wrapped in delimiters
- **WHEN** user messages and historical context are prepared for the LLM
- **THEN** user inputs are wrapped in `<user_message>` tags and memory facts are wrapped in `<memory_item>` tags

### Requirement: Typing indicator before generation
The system SHALL send a chat action indicator (`typing`) via `sendChatAction` before initiating the LLM generation process to signal to the user that work is in progress.

#### Scenario: Triggering typing state
- **WHEN** an eligible message is accepted for LLM generation
- **THEN** `sendChatAction` is invoked with `typing` for that `chat_id` prior to awaiting the LLM response

### Requirement: Outbound message chunking
Outbound messages generated by the assistant SHALL NOT exceed 2000 characters per message. If an outbound response exceeds 2000 characters, the system SHALL split the message into sequential chunks on paragraph or sentence boundaries and send each chunk sequentially.

#### Scenario: Short response under limit
- **WHEN** the assistant produces a response of 500 characters
- **THEN** exactly one outbound message is sent

#### Scenario: Long response over 2000 characters
- **WHEN** the assistant produces a response of 3200 characters
- **THEN** the text is split at paragraph or sentence boundaries into chunks each <= 2000 characters, and sent in order

### Requirement: Failure fallback reply
If LLM generation or delivery fails after one retry, the system SHALL send a single friendly Vietnamese fallback message ("Mình chưa làm được việc này, thử lại sau nhé.") to the chat, and log the detailed error server-side without leaking raw internal stack traces into the chat.

#### Scenario: LLM API failure
- **WHEN** the LLM API call fails or times out
- **THEN** the group or private chat receives the Vietnamese fallback message, and the real error is logged to stdout

### Requirement: Prompt security integration in conversational reply pipeline
The system SHALL evaluate incoming conversation messages against prompt security validation before triggering LLM generation. When a security violation or injection attempt is detected, the pipeline SHALL send a safe refusal reply directly and skip LLM generation.

#### Scenario: Security rejection in reply pipeline
- **WHEN** an incoming message to the bot triggers prompt security detection
- **THEN** the system sends the friendly safety refusal without calling the LLM API

### Requirement: Multimodal vision processing for photo messages
The system SHALL support processing incoming photo messages with vision-capable LLM models. When Gemini (`@ai-sdk/google`) is configured and an incoming message contains a photo URL, the system SHALL construct multimodal user content including the image and caption. When a text-only provider (e.g. DeepSeek) is configured, the system SHALL include an image description wrapper in the text prompt and proceed with generation without failing. In canned mode without LLM, the system SHALL reply with the standard canned reply. The system SHALL store the photo message in message history with a visual reference tag.

#### Scenario: Photo analysis with Gemini
- **WHEN** a user sends a photo with or without caption and Gemini is the active LLM provider
- **THEN** the model receives the image content along with user caption and responds grounded in both the image and conversational context

#### Scenario: Photo message with text-only provider
- **WHEN** a user sends a photo with a caption and DeepSeek is the active LLM provider
- **THEN** the system forwards the caption and an indication of the attached photo without throwing an error

#### Scenario: Photo message stored in conversation history
- **WHEN** an incoming photo message is processed
- **THEN** the message repository stores the user entry with caption and photo reference so future conversation turns retain context

### Requirement: Lottery ticket photo recognition and checking workflow
The system SHALL equip the LLM with lottery lookup tools and system prompt guidance so that when a user provides a photo of a Vietnamese lottery ticket, the assistant extracts the station, draw date, and ticket numbers, verifies the ticket via the lottery tool, and responds with a friendly Vietnamese result summary adhering to plain-text formatting constraints.

#### Scenario: User sends photo of lottery ticket
- **WHEN** a user sends an image of a Vietnamese lottery ticket asking to check results
- **THEN** the model inspects the ticket details from the image, invokes the lottery checking tool with the extracted station, date, and ticket number, and presents the winning outcome clearly to the user

#### Scenario: Unclear ticket image or missing details
- **WHEN** the image is too blurry to reliably read the ticket number, station, or draw date
- **THEN** the model politely explains which details could not be read and asks the user to confirm or re-enter the station, date, or number

### Requirement: Group member context injection in system prompt
When generating a reply for a group chat, the system SHALL inject a structured list of known group members into the system prompt under a `<group_members>` section, detailing each member's display name, alias/role, and notes. The prompt SHALL also clearly identify the active speaker's name and alias to enable accurate distinction between participants.

#### Scenario: Group message with registered members
- **WHEN** preparing the LLM prompt for a group message where members are registered
- **THEN** the system prompt includes the `<group_members>` XML block listing known members and explicitly indicates the current speaker

#### Scenario: Private chat or empty group members
- **WHEN** preparing the LLM prompt for a private 1-on-1 chat or when no additional members are recorded
- **THEN** the `<group_members>` block is omitted from the system prompt

### Requirement: Dynamic web scraping tool availability
The conversational reply pipeline SHALL dynamically include the Crawl4AI `scrape_url` tool in the LLM tool suite whenever a Crawl4AI API token is configured in effective settings or environment.

#### Scenario: User provides URL and asks questions about page content
- **WHEN** user message contains a web URL and asks for summaries or questions about the webpage
- **THEN** the model invokes `scrape_url` with the target URL, inspects returned page content, and incorporates the information into its reply

#### Scenario: No Crawl4AI token configured
- **WHEN** neither database nor environment contains a Crawl4AI API token
- **THEN** the `scrape_url` tool is omitted from the tool definitions or gracefully informs the model that web crawling is unavailable
