## MODIFIED Requirements

### Requirement: Outbound message chunking
Outbound messages generated by the assistant or background schedulers SHALL NOT exceed 1200 characters per message chunk to prevent exceeding Zalo API single-message payload limits on multi-byte Vietnamese text. If an outbound response exceeds 1200 characters, the system SHALL split the message into sequential chunks on paragraph or sentence boundaries and send each chunk sequentially.

#### Scenario: Short response under limit
- **WHEN** the assistant produces a response of 500 characters
- **THEN** exactly one outbound message is sent

#### Scenario: Long response over 1200 characters
- **WHEN** the assistant produces a response of 1800 characters
- **THEN** the text is split at paragraph or sentence boundaries into chunks each <= 1200 characters, and sent in order

### Requirement: Outbound delivery with Zalo Markdown and automatic plain-text fallback
The system SHALL deliver conversational responses to Zalo with `parse_mode: 'markdown'`. If the Zalo API rejects the message due to parsing or formatting errors, or if the underlying client returns a synthetic rejection message identifier (prefixed with `local-`), the delivery layer SHALL automatically retry delivering the message as unformatted plain text without `parse_mode` so that no response is lost.

#### Scenario: Successful Markdown message delivery
- **WHEN** the assistant generates a formatted response with Markdown styling
- **THEN** the message is sent to Zalo with `parse_mode: 'markdown'` and rendered with rich text styling

#### Scenario: Markdown parse error fallback
- **WHEN** Zalo API rejects a message sent with `parse_mode: 'markdown'`, or returns a `local-` message ID
- **THEN** the delivery layer immediately resends the text without `parse_mode`, delivering the unformatted text to the chat
